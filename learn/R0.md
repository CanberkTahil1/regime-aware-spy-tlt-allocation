# R0 — Scaffold, licences, safety

## In two sentences
v2 now has a locked Python environment, the shared quantkit library pinned by hash at v0.19.1, the copied
`/task` + advisor + reviewer workflow, and guards against committing data or secrets. The old v1 strategy was moved into
`legacy/` with only its import lines changed, and tests prove it still reproduces its own published numbers to ~1e-15.

## What happened, step by step
- Copied the workflow from naive-vs-optimal (`.claude/agents`, `.claude/commands`, the sibling guard hook) and adapted it
  to this charter; every copied file is listed with its source hash in `COPIED.md`.
- Moved v1 in two commits: `9500d51` (pure renames) then `58ec69f` (15 import lines). `tests/test_legacy_frozen.py`
  checks that nothing else changed.
- `tests/test_legacy_v1.py` runs v1's own `main()` (648-config grid → selection → 2020–25 test) on the cached
  `data/prices.csv` and compares all three committed tables. Outputs go to a temp folder, never over `legacy/results/`.
- `LICENSES.md`: Fed (public domain), Ken French (the disclosed relaxation), and why Yahoo and Cboe are out. All clauses
  were re-read from the raw page source on 2026-10-28.
- `make doctor` checks the environment; `.githooks/pre-commit` refuses data files, > 5 MB files and token-shaped secrets.

- D0.1 (advisor): `legacy/` is a package, so v1's generic names (`config`, `data`) can't shadow the new code.
- D0.2 (advisor): no Yahoo client is installed; a fake `yfinance` refuses every call.
- D0.3 (advisor): pin all three v1 tables; a missing data file is a red test, never a skip.
- D0.4 (advisor, after a miss): the test suite's total memory was ~2 GB with 16 parallel workers, over the 1.5 GB

- O0.1 (owner, pending): what to do with the Yahoo/Cboe file on the public GitHub repo.

## The one number to remember
v1's 2020–2025 test metrics reproduce with max abs diff **1.2e-15** (band 1e-12): the v1 baseline is exactly what v1
reported (Sharpe 1.00, CAGR 16.3%, on v1's own Yahoo data and v1's own accounting). R1 re-runs it on new data and honest
accounting.

## Concept check
A **characterization test** pins what code *does*, not what it *should* do. Before changing anything (data, accounting),
you freeze the old outputs; any later difference is then caused by your change, not by drift. The tolerance (1e-12)
allows only floating-point noise from newer numpy/pandas.

## Try it yourself (5 minutes)
`make legacy` — you should see 6 legacy tests pass, the slowest being `test_v1_main_reproduces_all_three_tables`
(~7 s, it re-runs v1's whole grid search).

## Interview questions
1. **Why reproduce the old strategy exactly before improving it?** So every later difference has a known cause. If v1
   didn't reproduce, I couldn't tell whether a change in results came from the new data, the new accounting or a bug.
   Matching to 1e-15 means the baseline row in the ladder is really v1.
2. **Why did you stop using Yahoo and VIX data?** Their terms bar automated collection (Yahoo) and storing or
   redistributing (Cboe), and v1 had committed both to a public repository. v2 uses public-domain Fed data, a disclosed
   Ken French proxy kept out of git, and realised volatility instead of VIX.
3. **How do you make sure a shared library doesn't change your results?** quantkit is installed from a git tag, not
   editable, and every run hashes each quantkit file it loaded against a pinned list. If a loaded file differs, the run
   fails.

## What could be wrong
One expectation failed this phase (E0.5, memory, fixed by D0.4): a reminder that a budget for a *total* needs a
measurement of the total. The characterization reproduces v1 *as written*: it does not make v1 right. v1's look-ahead (same-close execution),
free leverage and missing cash yield are all still in there; R1 is where they get fixed and measured.
