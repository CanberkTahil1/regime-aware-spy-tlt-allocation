# R5 review (quant-reviewer, one round, BEFORE the freeze and the run-once test; range b99e537..baa64d4)

Per the /task rule for a run-once step, the single review ran before `make freeze` and `make test-run`. No v2
test-window number existed. The reviewer checked this from the cache calendar (synthetic only) and from the absence of
reports/r5 and of the lock. Findings are verbatim; each disposition follows it.

**Reviewer verdict (verbatim):** "No v2 number for the test window exists yet. … The ordering, the prereg hashes and the
timing all hold. Four things should be fixed **before** `make freeze`, because the lock makes every engine file final:
- The dry run never exercises bills or financing (M1).
- A crash during the run would leave an unexplained 'started' record (M2).
- The quantkit pin is only checked after the run has completed (M3).
- No placebo is reported for the regime layers on the test window (M4)."

---

**[MATERIAL] M1.** The synthetic dry-run panel has bill = 0 and dt = 0 on every row after the first, so the only
end-to-end pre-run check never exercises cash, excess returns or financing. Where: src/rspy/testwin.py:57
(`days = np.r_[1, np.diff(idx.asi8) // 86_400_000_000_000]`). How I verified: … gives datetime64[us] 0.0 0.0
(pandas 3.1: asi8 is in microseconds, so the day count floors to 0). The dry-run metrics.csv shows bill_pa 0 for every
rung … Fix: compute days from the index in a unit-independent way, assert bill > 0 and dt ≥ 1/360 on every row in that
test, and re-run the dry run before freezing.

**Fixed.**
- `days` is now `np.diff(idx.values).astype("timedelta64[D]")`.
- `test_synthetic_panel_is_seeded_and_shaped_like_the_real_one` asserts bill > 0, dt ≥ 1/360 and Monday dt = 3/360.
- Re-run dry run: bill_pa 2.8%/yr on every rung; financing non-zero on L1, L2 and L5-lev; one family row with k > 1,
  matched-vol error 9.0e-8.
- The real panel was not affected: build.py does not use `asi8`, and the real dt ≥ 1/360 on every development row.

**[MATERIAL] M2.** Any exception after start_record leaves reports/r5/test_run.json at status "started" with no reason,
and the guard then refuses every rerun. Where: scripts/r5.py:131-134 … Fix: wrap compute/evaluate in try/except that
writes status "crashed" with the traceback and the stage (build / identity / evaluate) before re-raising.

**Fixed.**
- `scripts/r5.py --mode run` wraps the computation. On any exception the record gets status "crashed", the stage
  (`STAGE`: load / build / identity / evaluate), the traceback and a note that no statistic was written; then it
  re-raises.
- Test `test_a_crash_after_the_record_marks_it_crashed`, with a planted failure in build.
- Broken-input check: writing "started" instead of "crashed" fails the test; restored, it passes.

**[MATERIAL] M3.** The installed quantkit tree is not verified before the test run; the loaded-module pin check runs only
after outputs are written and the record is marked "completed". … Fix: call pin.verify() (the full tree) inside
freeze.guard before start_record, or make test-run depend on verify-pin.

**Fixed.** On the real repo root, `freeze.guard` now adds `pin.verify_pin()` (the full installed quantkit tree) to its
problems before `start_record`. The loaded-module check after the run stays as well.

**[MATERIAL] M4.** There is no placebo on the test window for the regime layers, and the 2022 panel is exactly where
"lower bond weight" and "skill" look the same. Where: spec/prereg.yaml r5_test.scope.excluded ("placebos"); D5.6 …
Fix: before the freeze, register a descriptive block-shuffled-gate placebo row for L6–L8 on the test (counted no), or
bind the README and crisis table to show the development placebo verdicts next to every test L6–L8 number.

**Fixed, via a new decision.** D5.8 (advisor, medium confidence; no disagreement with the reviewer, the advisor amended
its own D5.6) does both:
- The README and site are bound to the development placebo verdicts.
- `testwin.placebos` shuffles the L6 and L7 keeps (12-month blocks) and the L8 multiplier (21-row blocks) on test rows
  only, for seeds 0–99. It reports percentiles and p05–p95 with no verdict, and is one-directional.
- It was registered in prereg `r5_test.placebo_descriptive` and in variants.csv (`test_placebo_regime`, counted no)
  before the freeze. New prereg hash in the ledger.
